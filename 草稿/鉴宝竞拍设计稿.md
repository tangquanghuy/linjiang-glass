# 鉴宝竞拍 · 设计稿

街机第五个游戏。玩家在拍卖会上竞拍**未开封的整箱货**，箱内是一片隐藏的格子仓库；
靠仪器和拍卖师透露的情报推断箱里有什么，落槌后逐格开箱，用藏品实际价值对比自己花的钱，给评级。

代码：`arcade/auction-engine.js`（规则引擎，纯逻辑）、`arcade/auction.html`（页面）
检查：`npm run auction`（三宽度跑完整流程）、`npm run auction:shots`（出图到 `artifacts/auction/`）
视觉：`npm run auction:themes`（4 主题 × 桌面/手机 × 5 面板 ＋ 大厅内嵌，出图到 `artifacts/auction-themes/`）
模拟：`npm run auction:sim`（平衡）、`auction:dist`（真值分布）、`auction:trace`（单局追踪）

---

## 1. 一场拍卖的结构

- 一场 = 3 个标的箱依次上拍，共用一份资产（接街机共享钱包）。
- 开场公告**场次主题**（「本场以瓷器为主」），这是玩家和竞拍人共同的先验分布。
- 每箱 **5 个回合**。每回合：拍卖师与仪器发情报 → 所有人**各自填一次价**（自由金额，
  不是固定加价阶梯）→ 填完当回合公开。每回合 30 秒，超时按放弃处理。
- 五回合走完，**全场出价最高者得**，成交价就是他那一口价。
- 落槌后逐格开箱，结算：藏品实际价值 −（成交价 + 佣金 + 钻验花费），给 S~F 评级。

仓库是 7×6 = 42 格，箱内 4~9 件，每件占一个矩形（1×1 到 3×3）。开局全部隐藏。

**为什么是自由填价而不是「加一口」**：固定阶梯的英式加价会让玩家每回合被动跟价，
情报窗口被压扁；自由填价才有跳价威慑、试水低价、最后一口偷袭这些决策。
早期版本用固定阶梯，实测玩家拿下率只有 7~12%，而且回合数当落槌条件会导致
玩家先出价、竞拍人后出价，最后一口永远落在竞拍人手上。

## 2. 三层信息模型（整套数值的骨架）

这是本作唯一真正的设计核心，其他都是它的推论。

| 层 | 来源 | 谁能看到 | 作用 |
|---|---|---|---|
| 公开情报 | 拍卖师逐回合透露 | 所有人 | **只降低风险，不产生利润**。所有人一起看清，出价同步抬高 |
| 私有情报 | 玩家带的仪器 | 只有玩家 | **利润的唯一来源**，而且越早拿到越值钱 |
| 行为情报 | 每回合公开的出价槽 | 所有人 | 谁在第几回合跳了价，本身就是线索 |

引擎里的落点：竞拍人估值 = `真值^α · 先验^(1−α) · exp(N(0,σ))`。
每条公开情报都往 α 上加（`PUBLIC_WEIGHT`），所以出价随回合逼近真值。

由此推出的仪器定价规则：同样是「看清全部」，第 1 回合要 3 个装备位，第 4 回合只要 1 个。
**模拟已经验证了这条**：大型品鉴仪（R4 展示全部品类）的 ROI 是 **0.0%** —— 
到第 4 回合，公开情报已经把别人的出价推到接近真值，看清了也没得赚。

「当前估价」只把**已探到的格子**算进去，没探到的一律算 0。所以它是一个下限而不是猜测，
而且学到坏消息（验出赝品、品质是普品）时会往下走。玩家看到的永远是「我已确认的价值」，
不会被一个虚高的期望值推着去抬价。

## 3. 竞拍人（纯代码，不调任何模型）

6 个人格，每箱随机上座 4 位。参数：

- `insight` 眼力 —— 只决定估值噪声 σ，**不是能看见真值**
- `margin` × `aggression` —— 乘积 k 是他愿意出到自己估值的几成，现有人格 k 在 0.42~0.78
- `patience` 耐性、`tilt` 上头概率、`jump` 跳价幅度、`bias` 偏好品类、`budgetMul` 预算
- `BID_RAMP = [.46 .62 .76 .89 1.0]` —— 每回合出到上限的几成，前面试水后面压上去。
  这条曲线让「早出价便宜」成立。

> 后续要让语言模型扮演竞拍者，只换 `rivalBid()`，估值与上限的算法照旧复用。
> 但平衡必须靠这套参数化模型跑蒙特卡洛来定，模型输出没法调经济。

## 4. 平衡过程中修掉的四个结构性问题

都不是「调参数」能解决的，而且很容易再犯。

**① 竞拍人不能看穿真值。** 第一版让竞拍人按 insight 概率知道每件拍品的真值，结果市场变得
有效：好箱子被抢走，烂箱子留给玩家。拿下率 1.3%，赢的时候平均付真值的 **4.2 倍** ——
教科书级的赢家诅咒。改成「弱但真实的信号」（真值与先验的几何插值）才有可打败的空间。

**② 但也不能完全不含真值信息。** 把真值信息删干净之后，竞拍人出低价只是噪声、不含坏消息，
玩家跟着捡就是白拿钱：无技能盲拍 ROI **+67%**，反而是最优解。逆向选择必须存在，
只是强度要可调 —— 那就是 α。

**③ 回合数不能当落槌条件。**（见 §1）

**④ 真值分布不能太偏斜。** 品类密度原本跨 10 倍（家具 420 / 钱币 4200），箱子的品类构成
直接决定价值量级，真值/先验 的中位数只有 0.71、p10 0.23 —— 四分之一的箱子价值不到期望的
四成。这种分布做不出捡漏，只能做出「箱箱亏钱、偶尔暴富」。压缩密度跨度到 3.5 倍、
收窄稀有度尾巴（孤品 13→7 倍）之后：**mean 1.00 / 中位 0.89 / p10 0.41 / p90 1.71 / p99 2.74**。

另记一笔：`packItems` 会丢弃放不进格子的拍品，实际件数低于抽样件数，解析式先验会系统性
高估。用主题上的 `calib` 校正。
**改动 GRID / 形状池 / 件数区间之后必须重跑 `npm run auction:dist` 重新标定。**
（这条是自己踩出来的：仓库从 6×5 扩到 7×6、件数从 3~7 改成 4~9 之后，装箱损耗几乎消失，
旧的 calib 立刻让 mean 漂到 1.11。现在这批 calib 全都接近 1.00 就是因为大仓库几乎不丢件。）

## 5. 当前数值状态

`npm run auction:sim -- --n 1200`（3 箱/场，4 位竞拍人，机器人 margin 固定 0.22，只变装备）

| build | 位 | ROI | 净收益/场 | 拿下率 | 成交/真值 |
|---|---|---|---|---|---|
| 空手（对照） | 0 | −2.4% | −774 | 27.8% | 1.02 |
| 小型品鉴仪（R1 轮廓） | 1 | −1.4% | −628 | 34.8% | 1.01 |
| 估价镜（R1 看清一件） | 3 | **+1.9%** | +740 | 30.4% | 0.98 |
| 验伪灯（R2 标赝品） | 2 | −0.5% | −139 | 26.9% | 1.00 |
| 大型品鉴仪（R4 全品类） | 1 | **−2.9%** | −939 | 27.8% | 1.03 |
| 下午茶（R1/R3 轮廓） | 2 | −4.8% | −2,075 | 33.7% | 1.05 |
| 加密出价器 | 1 | **−15.5%** | −8,493 | 48.0% | 1.18 |
| 小型+验伪+熟客 | 4 | **+7.1%** | +2,618 | 31.0% | 0.93 |
| 估价镜+熟客 | 4 | +6.9% | +2,501 | 30.4% | 0.94 |

拿下率落在 27~48%（一场三箱拿下约一箱），成交/真值 0.93~1.18，评级以 B 为中心铺开 S~F。
**空手是 −2.4%**，盲拍确实赔钱；装满四个装备位能到 +7%。晚期情报（大型品鉴仪 R4）
和空手没有区别 —— 这正是「越晚拿到的私有情报越不值钱」在数值上的验证。

### 两个「新手陷阱」

模拟意外跑出两个负收益的装备，而且原因都很扎实，值得当成设计资产而不是 bug：

**加密出价器 −15.5%。** 它把「威慑」拿掉了：出价公开时，一口高价能把竞拍人吓退；
藏起来之后他们照旧往上加，于是拿下率涨到 48% 而成交/真值 1.18 —— **赢得多、赢得贵**。

**下午茶（纯轮廓）−4.8%。** 只知道占几格、不知道品类品质，「当前估价」会按均值给这些格子
估价，于是玩家对垃圾箱也产生了信心并跟着抬价。**轮廓情报单独用是有害的**，必须和
品类/品质情报搭配才成立。

两条都是真实的博弈结论。但作为可选装备，它们目前的定价（1 位 / 2 位）明显偏贵，
要么重新定价，要么改设计 —— 比如加密出价器改成「只在最后一回合隐藏」，让它从
「全程隐身」变成「偷袭工具」。

**未解决**：
- 参考机器人不会读行为情报（第三层完全没被验证），也不会拿加密出价器做偷袭。
- 佣金 8%、`BID_RAMP`、`PUBLIC_WEIGHT` 三个旋钮都还没扫过。
- 上面两个陷阱装备的定价。

## 6.5 视觉巡检发现的问题（`npm run auction:themes`）

只看暗色主题的几张图就交付是不够的：这个页面要跟着街机切四套主题，还要嵌在大厅的
iframe 里。补了 `scripts/shot-auction-themes.mjs`，把 4 主题 × 桌面/手机 × 5 个面板
（装备、竞价、键盘、开箱、总账）＋ 大厅内嵌视图全部拍下来逐张看。找到并修掉：

**① `color-scheme` 不能写在 `:root` 上。** canvas 底色是按根元素的 color-scheme 画的，
根元素一旦声明 `dark`，浏览器就用暗色填满整页背景，**即使 html/body 都是 transparent**。
结果是页面嵌进大厅后，拍卖厅以外的区域全是黑的，透不出大厅自己的底色 —— 浅色主题下
像开了个洞。只能挂在 body 的各主题选择器上。这条对其余四个街机页面同样成立，
它们是满屏布局所以一直没露出来。

**② 表面层次不能靠半透明黑堆。** 深色底上 `#00000030` 是漂亮的凹陷，浅色底上同一个值
只会糊成一片脏米黄。后果最严重的地方是仓库：**「未探格」和「已探到轮廓的格子」几乎同色，
核心信息显示直接失效**。改成主题化的 `--sunk / --sunk2 / --fog / --found / --scrim`，
未探格带斜纹压暗，已探格必须明显更亮。

**③ 遮罩层不能用 `position:fixed`。** 在 `fit:content` 的 iframe 里，「视口」是 iframe
的盒子，于是遮罩会把拍卖厅下方的空白一起刷暗。改成 `.hall` 内的 `absolute`，
只盖住拍卖厅面板本身。相应地 `.hall` 要有 `min-height`，否则开场时三栏都是空的、
面板会被压成一条缝。

**④ 窄屏的面板会跑到屏幕外。** 竖排的拍卖厅有近两千像素高，面板在其中居中就等于看不见。
改成窄屏顶部对齐，并且打开时 `scrollIntoView` —— 同源 iframe 里这会带动外层大厅一起滚。

**⑤ 承载信息的小字全部偏小偏淡。** 8~8.5px + `--dim` 在浅色主题上基本读不出来
（场次公告、竞拍人台词、出价槽、品质色例、装备条）。统一上调到 9.5~10px 并换成 `--muted`。

**⑥ 杂项**：背景巨字 `AUCTION ENDED` 用白色 4% 透明，浅色主题上完全看不见；
装备位不够的卡片压到 .36 等于消失；空手时「入场」被禁用（空手是合法打法，不该禁）；
总账里没拍到的箱子收益写 0 会被读成「打平」。

另外记一条截图方法论：开箱格子有 0.26s 入场动画，不等它跑完就截图，拍到的是一箱
opacity 0 的空格子 —— 我据此误判过一次「渲染 bug」。检查脚本现在会等动画并断言
`#resultVault .it` 数量非零。

## 6.6 布局：从「小盒子居中」改成整屏应用

第一版把 `.hall` 卡在 `width:min(100%,1180px)` 上、高度由内容决定，并在大厅里注册成
`fit:'content'`。宽屏下的结果是缩在中间一小块、下面一大片空，字也显得特别小。

改动：大厅里改成 **`fit:'viewport'`**（和每日一签同类），页面本体变成
`html,body{height:100%}` + `.hall{flex:1;display:flex;flex-direction:column}`，
顶栏 / 三栏 / 底部操作台各自 `flex`，三栏内部各自滚动 —— 竞价时视线要在
「仓库 / 情报 / 对手」之间来回跳，整页一滚就全乱。

**但「填满」不等于「拉伸内容」。** 中间过程试过给座位卡和情报卡 `flex:1`，
结果变成一排胖空盒，比留白更难看。参考游戏能容忍留白是因为背后有 3D 场景当画面；
纯面板布局里，空白只会被读成 bug。最后的做法是：

- 内容保持自然密度、顶部对齐；超宽时 `.hall{max-width:1560px;margin:0 auto}`，
  不硬撑到 2000px 去制造空洞。
- 把 **出价台**（起拍价 / 推荐参考 / 明面最高 / 你的最高）从中栏底部挪到**底部操作台整宽**，
  和装备条、放弃 / 出价一起构成一条有分量的控制台，给整屏压住底。
- 右栏底部补 **可用资金 / 佣金 / 钻验花费** —— 仓库是 7:6 的方阵，高度总吃不满，
  剩下的空间用真正有用的数字补上，而不是留个洞。
- 情报栏前几回合必然是空的，直接写明「后面 N 个回合的情报会继续累积在这里」。
  提示不要画虚线框：一个 400px 高的空框子看起来像没做完。

### 两个 aspect-ratio 的坑（都会造成元素互相盖住）

**① `max-height:100%` 对 `aspect-ratio` 元素不生效。** 仓库用
`width:100%` + `aspect-ratio` + `max-height:100%` 时，在弹性容器里拿不到确定的百分比基准，
实测溢出容器 48px，正好盖住下面的品质色例 —— 看起来像色例被删了。
正确写法是反过来：**按高度定尺寸、宽度用 aspect-ratio 反推**（`height:100%;width:auto`），
并给容器加 `overflow:hidden` 兜底。

**② 但这条不能写成全局规则。** 结算面板里的仓库父容器高度是 `auto`，`height:100%` 同样
拿不到基准，于是仓库撑爆、盖住了「下一箱」按钮，自动化脚本表现为「点了 288 次没反应」。
所以只给 `.vault-fit > .vault` 用按高度定尺寸，默认仍是按宽度。

查这类问题最快的办法是 `document.elementFromPoint(按钮中心)` —— 它直接告出是谁盖在上面。

## 7. 界面

三栏：左边竞拍人（头像 + 名牌 + 5 个出价槽，公开出价就是行为情报的载体），
中间回合标题 + 情报卡堆，右边仓库网格 + 当前估价。底部装备条 + 放弃 / 出价。
出价走数字键盘浮层（推荐出价参考、明面最高、可输入范围、×2、上轮出价）。
落槌进「竞拍结束」：三宫格数字 + S~F 评级 + 吐槽，右侧整箱逐件翻开。

窄屏把仓库顶到最上面 —— 它是判断依据，必须和出价按钮同屏可见；场次公告折到第二行整宽显示，
那是本场的先验分布，不能因为窄就藏掉。

`?nolimit=1` 关掉回合计时，给自动化检查和手动调试用。
