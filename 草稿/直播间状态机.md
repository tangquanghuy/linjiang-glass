# 直播间状态机 · 规则说明

先定规则，后写代码。本文只描述「后台怎么算、什么进 MVU、什么给 AI 看」。直播页立绘、头像、档期显示按同一份约定改，不另起一套数。

---

## 1. 这件事解决什么

直播页现在是一张静态示例：人气写死、航海和高能榜写死、送礼只扣钱。真进酒馆之后，这些数必须：

- **跟这条聊天记录走**：换聊天等于换档，不串档。
- **不喂给 AI**：航海人数、人气精确值、高能榜名单是界面和脚本的事。模型去编排榜一、编造人气涨了八百，会和 HUD 打架。
- **按真直播间的感觉动**：玩家一送礼，人气先跳、人数后跟；房间里要有 NPC 榜一当对手，而不是空榜等玩家一个人刷。

AI 仍然需要知道的，只有「她开不开播、标题是什么、大概多少人、玩家在不在这间房、玩家自己的牌子和累计打赏」。场面细节由 HUD 演。

---

## 2. 给 AI 看 / 只给后台

对照 `参考/mvuzod.js`：战斗倍率、组合技能槽、简详显示都放在顶层 **`系统配置`** 里。它跟着 MVU `stat_data` 存进**当前聊天**，所以有聊天级隔离和持久化；辅助脚本读写，变量注入默认不把这一棵树摊给模型。

本项目同样加一棵 **`系统配置`**，直播相关只进这里。现有给叙事用的字段不动。

| | 给 AI（现有或只回写整数） | 只给后台（系统配置） |
|---|---|---|
| 开不开播、标题 | `对象信息.{名}.直播.开播 / 标题` | — |
| 房间规模 | `直播.人数`：由状态机回写成**约数**（如 18200，不要 18247） | 精确 `人气`、`在线`、本场礼物热度 |
| 玩家粉籍 | `玩家信息.粉丝身份.{名}`：关注、累计打赏、牌子档位/天数、房管、禁言 | — |
| 人在哪间房 | `玩家信息.所在直播间` | — |
| 大航海 | 不写名单、不写精确人数 | 航海人数、NPC 舰长/提督/总督名单 |
| 高能榜 | 不写 | NPC + 玩家本场消费榜 |
| 对手 | 不写 | 榜一种子、还手预算、本场已花 |

辅助脚本要像参考项目冻「简略显示羁绊」那样：**拦住 AI 改 `系统配置`**。这一棵只能由脚本和 HUD 写。AI 若给 `/系统配置` 打补丁，整段回滚。

档期本身不是变量。七个人的开播习惯写在 HUD / 世界书里（`src/data.js` 的 `stream.schedule`），不进 MVU，避免模型改她周几休。

## 3. 系统配置里一张房一张表

`系统配置.直播间.{短名}`，短名与 HUD 一致：东雪莲、塔菲、沙花叉、时雨羽衣、红蔷薇、斯黛拉、璃亚梦。第一次进这间房（或本聊天第一次开播）时，按她的档位**生成并写死**种子，之后只更新，不重抽。

每间房至少有：

- **底盘**：这人常态有多热。只在本聊天第一次生成，后面开播都用它。
- **人气**：顶栏那个数。送礼先打在这里。
- **在线**：真在看的人数。跟人气分开，涨得慢、掉得也慢。
- **本场热度**：这场已经靠礼物堆上去的「虚火」，下播清掉。
- **高能榜**：若干 NPC + 玩家本场消费。历史累计可另记，用来让榜一像老熟人。
- **大航海**：NPC 三档人数 + 若干具名位（不必七个全具名，有几个常客就够）。
- **种子**：随机源。同一聊天同一主播，重进房间对手还是那些人。

`对象信息.{名}.直播.人数` 只在状态机跑完后回写一次，取 `人气` 与 `在线` 里更适合当「场面」的那个，再按百或千收成约数。模型看到的是「大概一万八」，不是内部账。

---

## 4. 底盘：谁热、谁冷

按现在样本里已经在播的量级定档，不要七个人一样热。

| 档 | 谁 | 底盘人气大约 | 在线大约 | 大航海大约 |
|---|---|---|---|---|
| 头牌晚间 | 塔菲 | 1.6 万～2.0 万 | 人气的 0.7～0.9 | 舰长 20～40 |
| 深夜小房 | 璃亚梦 | 5 千～8 千 | 同上比例 | 舰长 8～15 |
| 常规晚间 | 东雪莲、沙花叉、斯黛拉、红蔷薇 | 2 千～6 千 | 同上 | 舰长 4～12 |
| 周更 | 时雨羽衣 | 8 百～2 千 | 同上 | 舰长 1～5 |

本聊天第一次生成时在区间里抽一个整数当底盘，以后沿用。提督、总督是稀的：头牌房可以有 1～3 提督、0～1 总督；小房经常是 0。

## 5. 开播、下播、档期

世界时钟和星期来自 `世界信息`。档期来自 HUD 那张表，例如：

- 塔菲：20:00–23:30，周一、二、四、五、六、日，周三休（晚间主档）
- 东雪莲：21:30–00:30，周日休（深夜杂谈）
- 沙花叉：21:00–00:30，一、二、四、五、日
- 时雨羽衣：22:00–00:30，仅周三、周日
- 红蔷薇：19:00–22:00，三六休（黄昏音乐台）
- 斯黛拉：18:30–21:30，周一休（傍晚电台）
- 璃亚梦：23:00–02:00，周二休（深夜互动）

跨零点的档（莲、叉、羽衣、璃亚梦）按「开始 ≥ 现在或现在 ≤ 结束」算在播窗里。

四种状态与日程表一致：

- **正在播**：今天有档，且现在在时间窗里，且 `开播` 为真。
- **临时开播**：`开播` 为真，但今天没档，或有档却不在窗里（璃亚梦样本就是夜场提前开）。
- **今日休播**：今天有档，窗也到了，但 `开播` 为假。
- **固定档**：今天有档，还没到点 / 已经过了，且没在播。

状态机只在 **正在播 / 临时开播** 时跑礼物和人气。休播或没进房，榜和人气冻结。

下播或换日：

- 本场热度清零，人气回到底盘附近（允许 ±5% 的慢漂，不要一场火箭把第二天底盘抬飞）。
- 高能榜本场消费清零；NPC 的「这人是老登」身份保留。
- 玩家 `累计打赏`、牌子档位留在 `粉丝身份`，本场消费清零。
- 大航海人数几乎不动，只随办卡 / 到期缓变。

直播页顶栏的时间文案用档期，不写死「晚间主档 20:00–23:30」。塔菲就用她那行；以后同一套页切到璃亚梦，就显示 23:00–02:00、深夜互动。

## 6. 人气怎么涨（核心）

人气不是在线人数的别名。真直播间里：礼物先打人气，推荐位和进房有滞后，所以人数跟在后面。

**人气 = 底盘 + 本场热度的当前残留**

本场热度只来自礼物和办卡，不来自口嗨。

### 6.1 单笔换算

用金额当燃料，但不是 1 元 1 人气。小礼物几乎没水花，大礼物才配跳一截。建议点数（可微调，不要改成线性「金额×常数」一条直线）：

| 东西 | 金额 | 人气点数 | 在线跟进（上限） |
|---|---|---|---|
| 小心心 | 0 | +1～2，可忽略 | 0 |
| 辣条 | 1 | +8 | 几乎 0 |
| 干杯 | 20 | +70 | +10 以内 |
| 心愿盲盒 | 50 | +150 | 很少 |
| 情书 | 100 | +400 | +40 左右 |
| 小飞机 | 200 | +900，可飘屏 | +80 |
| 摩天大楼 | 520 | +2200 | +150 |
| 火箭 | 1288 | +8000 | +400 |
| 舰长 | 138 | +500，航海 +1 | +30 |
| 提督 | 1998 | +9000 | +250 |
| 总督 | 19998 | +40000 | +800 |

在线跟进是「目标增量」的上限，不是立刻加上这么多人。小心心和辣条不该让人数可感地动。

连送：同一玩家 30 秒世界时（或连续两条送礼结算）内连刷，第二笔起人气按 85%、70%、55%……下限 40%。刷辣条不能把房间刷成火箭场。

### 6.2 人数怎么跟

每次送礼后立刻：人气 += 点数。

在线人数走向一个目标：

`在线目标 = 底盘在线 × (1 + log10(1 + 本场热度 / 底盘人气))`

然后每过一个「节拍」（一条世界时间推进、或一次脚本结算）把现在的在线往目标靠一截，大约两三成，不要一次拉满。火箭之后人气可以先到两万八，人数在几分钟世界时里从一万六爬到两万出头。

没有新礼物时：本场热度按节拍衰减（例如每节拍掉 8%～12%，掉到本场热度的一个地板为止）。人气跟着掉回底盘。在线掉得更慢。这是下播前房间「凉下去」的感觉。

### 6.3 回写给 AI 的人数

取当前人气，按百位（小于一万）或千位（大于一万）收整，写入 `直播.人数`。样本塔菲 18240 → 显示「1.8万」，内部人气可以是 18240，送礼后内部 26300，AI 看到 26000 或 2.6万。不要把高能榜金额写进任何给模型的字段。

## 7. NPC 对手（高能榜）

每间房固定生成 4～7 个 NPC，本聊天内名字不变。头牌房里要有一个明显的榜一种子，本场开工消费大约在 200～800（塔菲）或 50～200（小房），让玩家送一杯干杯还上不了第一，送情书或飞机才开始咬榜。

规则：

- 榜按**本场消费**排。玩家送礼立刻入榜或刷新自己那一行。
- NPC 不是每秒都在砸。只在这些时候动：玩家刚进房（已经有几笔历史感的小礼物摊在榜上）、玩家送出 ≥ 干杯、玩家刚刚把榜一抢走。
- **还手**：玩家以单笔 ≥ 100 抢走榜一后，有约三成机会，榜一 NPC 在下一拍用干杯～情书量级回一笔，且本场还手总预算有封顶（头牌大约 1500～3000）。预算用尽就认输。防止无限 NPC 钱包。
- 总督级还手禁止。NPC 不办提督/总督来压玩家。
- 名字用临江池子（云庭、湖滨、鼓岭、西洲加班那一套），不要平台网名腔。同一聊天同一主播不要刷新成另一批人。

办卡进航海名单，不替代高能榜。航海是订阅位，高能榜是这场花了多少钱。

---

## 8. 大航海

数量跟底盘走，几乎不跟人气尖峰走。玩家开通舰长/提督/总督：

- 写入 `粉丝身份.牌子档位` 和剩余天数（30 天，已有规则：三档不同时叠）。
- `系统配置` 里该房对应档 +1（若玩家本来不是这档）。
- 具名位里插入「你」，方便 HUD 大航海页。

NPC 舰长到期、人数微涨微降，只在换日时动一点点（±1 内），不要一场火箭航海翻倍。

AI 看不到航海名单和人数。叙事里「舰长弹幕优先」继续只看玩家自己的 `牌子档位`。

---

## 9. 和已有结算怎么接

送礼与办卡的金钱、累计打赏、牌子等级、念 ID 概率，仍按 `变量相关/送礼与喜好.md` 和现有 `粉丝身份` / `badgeLevel`。状态机**额外**做三件事：改人气/在线、改高能榜、改航海后台账。

仍然成立：

- 打赏不买好感。人气不是好感。
- 总督不买服从。
- 小心心点了就送，不弹窗；花钱的才确认数量。小心心几乎不推动人气和人数。

玩家 `金钱` 不足则整笔取消，状态机不跑。

## 11. 节拍（什么时候算一次）

酒馆不是实时帧。建议这些时刻跑状态机：

1. 玩家确认送礼 / 办卡 / 醒目留言（立刻算人气和榜）。
2. 世界时钟推进（辅助脚本换时段、换日时衰减、下播清本场）。
3. 玩家进入某间房（若本聊天还没有这间房的种子，生成 NPC 和底盘）。

不要每条弹幕都算人气。NPC 还手挂在第 1 类事件的「下一拍」，不要让模型去写还手。

---

## 12. 明确不做

- 不把高能榜、航海名单、精确人气塞进世界书或变量注入。
- 不让 AI 生成榜一名字或改 `系统配置`。
- 不用真实平台接口，金额是本游戏的 金钱。
- 不把人气公式做成「金额×固定倍数」一条直线，也不做成无上限滚雪球。
- 不在休播时继续涨人气。
- 第一轮代码先落地：系统配置 schema、进房种子、送礼驱动人气/榜/航海、约数回写 `直播.人数`、直播页换头像立绘和档期。NPC 还手和热度衰减可以紧跟，但不要先做弹幕模拟器。

---

## 13. 正文标签：AI 只交这一拍的戏，界面去填真数据

以后玩家进房时，模型像工具调用那样丢一块标签。正文美化按块切开、渲染成直播页。人气、航海、高能榜、头像立绘**不写在标签里**，渲染时从 MVU / 系统配置读。

开闭标签只包**整间房**，不要每条弹幕再套一层。对齐智慧姬 `<DiceCombat>`：外壳里一行一个 `键: 值`；弹幕是列表，所以 `弹幕:` 下面用 `- ` 一行一条。稳的不是空格切位置，也不是 XML 嵌套，而是**键名当分界**：每条里面写 `类型:` `名字:` `内容:`，解析时找这些键，不按空格数第几段。

### 外壳

```
<LiveRoom>
…
</LiveRoom>
```

解析时同时认 `<直播间>`。优先 ASCII 名，中文正文里几乎不会误撞。整段放在回复**开头或末尾**，不要夹在段落中间。`所在直播间` 有人时，这一拍最多一块。

### 房间级只许这些键

| 键 | 必填 | 含义 |
|---|---|---|
| 主播 | 是 | 短名：东雪莲 / 塔菲 / 沙花叉 / 时雨羽衣 / 红蔷薇 / 斯黛拉 / 璃亚梦。别名（永雏塔菲等）解析时折成短名。 |
| 主播说 | 否 | 她这一拍嘴里说的话。可空。不要把小说旁白塞进来。 |
| 弹幕 | 否 | 下面若干行，每行一条，以 `- ` 开头。建议 0～8 条。 |

禁止出现：人气、人数、标题、金钱、高能榜、大航海、礼物栏、关注按钮。那些由后台填。

### 弹幕一行一条

不要写成 `- 普通 云庭7楼: 来了`（空格切位置，昵称一带空格就歪）。不要写成每条 `<弹幕>…</弹幕>`（体积和出错面都放大）。

写成：

```
- 类型: 普通 名字: 云庭7楼 内容: 来了，电梯刚好卡在十三层
```

同一行里几个 `键: 值` 挨着写。键与键之间一个空格即可，不必分号、不必换行。

| 键 | 何时要写 | 含义 |
|---|---|---|
| 类型 | 每条都要 | 只能是：普通、舰长、提督、总督、礼物、醒目留言、进入、系统 |
| 名字 | 系统以外都要 | 发言者昵称，可含空格 |
| 内容 | 说话类都要；进入、礼物可空 | 必须写在**该行最后**。礼物缺内容时，界面用「礼物名 × 数量」拼一行 |
| 礼物 | 仅礼物 | 礼物短名，如 干杯、火箭 |
| 数量 | 仅礼物 | 正整数，缺则当 1 |
| 金额 | 仅醒目留言 | 正整数，如 30、50、100 |

类型写错则当普通。不要写 普、舰、提、督、礼、SC、进、系。未知键丢掉。缺必填键的那一行丢掉，不要拖垮整房。

解析顺序：

1. 用开闭标签取出整块 `<LiveRoom>`（或 `<直播间>`）。
2. 按行读房间字段。`主播` / `主播说` 当行取值。`弹幕:` 本身可空，随后所有以 `- ` 开头的行都是弹幕，直到块结束。
3. 切字段：去掉行首 `- ` 和首尾空白；认半角 `:` 或全角 `：`。在一行里扫描这些键名：`类型` `名字` `礼物` `数量` `金额` `内容`。某个键的值 = 它的冒号之后、下一个键名之前的整段，去掉首尾空白。
4. **`内容` 必须在该行最后**，它的值吃到行尾，所以正文里可以有空格、冒号、数字，也不会被拆成别的字段。

不要用竖线表，不要用嵌套标签，不要把类型和名字当成位置参数用空格切开。

### 完整例子

```
<LiveRoom>
主播: 塔菲
主播说: 辛苦了。今晚先把加班那条醒目留言念了。
弹幕:
- 类型: 普通 名字: 云庭7楼 内容: 来了，电梯刚好卡在十三层
```

### 给模型的短指令（以后贴世界书）

玩家在直播间时，回复末尾输出且仅输出一块 `<LiveRoom>`。里面写 `主播: 短名`，可选 `主播说: 这一拍她说的话`。可选 `弹幕:`，下列 0 到 8 行，每行一条，格式 `- 类型: … 名字: … 内容: …`。礼物行加 `礼物:` `数量:`，醒目留言行加 `金额:`，`内容` 必须写在该行最后。类型必须写完整词，只能是：普通、舰长、提督、总督、礼物、醒目留言、进入、系统。不要写人气、标题、榜、航海。不要用表格，不要给每条弹幕再套一层标签，不要用空格拼类型和名字。
